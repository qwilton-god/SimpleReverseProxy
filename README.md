# Go Reverse Proxy & Load Balancer

Реализация отказоустойчивого реверс-прокси на языке Go с поддержкой балансировки нагрузки. Проект разработан для изучения механизмов работы протокола HTTP, управления сетевыми соединениями и обеспечения конкурентности.

## Технологический стек
- **Language:** Go (стандартная библиотека `net/http`)
- **Concurrency:** `goroutines`, `atomic`, `sync.RWMutex`
- **Config:** JSON-based
- **Logging:** `slog` (structured logging)

## Функциональные возможности

### 1. Балансировка трафика
Реализован алгоритм **Smooth Weighted Round Robin**. В отличие от простого выбора по весам, данный алгоритм обеспечивает максимально равномерное распределение запросов во времени, предотвращая пиковые нагрузки на отдельные узлы.

### 2. Отказоустойчивость (Health Checks)
Фоновый воркер выполняет периодическую проверку доступности бэкендов (TCP Dial). 
- При неудачной проверке сервер исключается из ротации.
- При восстановлении связи сервер автоматически возвращается в пул.
- Параметры проверки вынесены в конфигурацию.

### 3. Проксирование и сетевая логика
- **Hop-by-hop Headers:** Реализована корректная фильтрация заголовков, специфичных для конкретного соединения.
- **Context Propagation:** Контекст входящего запроса пробрасывается в исходящий. При разрыве соединения со стороны клиента прокси немедленно прекращает ожидание ответа от бэкенда.
- **X-Forwarded Headers:** Поддержка проброса реального IP адреса, хоста и протокола через `X-Forwarded-For`, `X-Forwarded-Host` и `X-Forwarded-Proto`.
- **Stream Copying:** Использование `io.Copy` для передачи тела ответа без промежуточной аллокации памяти под весь объем данных.

## Структура проекта

```text
├── cmd/
│   ├── proxy/          # Исполняемый файл прокси-сервера
│   └── server/         # Тестовые бэкенды для эмуляции нагрузки
├── pkg/
│   ├── proxy/          # Ядро: балансировщик, пул соединений, хендлеры
│   └── config/         # Логика загрузки и валидации настроек
├── config.json         # Параметры балансировщика и список бэкендов
├── server.json         # Параметры портов для бэкендов
└── Makefile            # Команды для сборки и запуска
```

## Конфигурация

Пример файла `config.json`:
```json
{
  "proxy_port": ":8080",
  "servers": [
    { "url": "http://127.0.0.1:8081", "weight": 5 },
    { "url": "http://127.0.0.1:8082", "weight": 1 }
  ],
  "health_check_interval": 10
}
```

Пример файла `server.json`:
```json
{
  "server_ports": [
      "8081",
      "8082",
      "8083"
  ]
}
```
## Запуск

1. Запуск группы тестовых серверов:
   ```bash
   make run-servers
   ```
2. Запуск прокси-сервера:
   ```bash
   make run-proxy
   ```

## Безопасность и ограничения
- **Graceful Shutdown:** Перехват сигналов `SIGINT/SIGTERM` для корректного завершения активных соединений.
- **Body Limit:** Ограничение размера входящего тела запроса (10MB) для предотвращения атак на переполнение памяти.
- **Timeouts:** Установлены жесткие лимиты на чтение/запись и ожидание ответа от бэкендов.
